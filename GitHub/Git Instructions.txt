GITHUB UPDATE INSTRUCTIONS - Photo Downloader
=============================================

Repository: https://github.com/RexAlfes/Photo-Downloader
Website:    https://rexalfes.github.io/Photo-Downloader/   (served from the docs folder on main)

WHAT GOES WHERE (unzip PhotoDownloader.<version>.zip first, for example PhotoDownloader.0.1.1.1.zip)
------------------------------------------------------------
See also GitHub/Two_Computers_Guide.txt (working on two computers, pull/commit/push).
Normal upload   : *.pas, *.lpr, *.lpi (PhotoDownloader.lpi), *.ico, README.md, .gitignore, .github/FUNDING.yml, .github/workflows/build.yml
Manual, as needed: the User Manual. Copy GitHub/docs/User_Manual.md into the repository's docs folder
                  (README.md links to it) whenever it changes.
Manual, as needed: the website page. Copy GitHub/docs/index.html into the repository's docs folder
                  only when you want the public site to change.
Never uploaded  : the PhotoDownloader\docs and PhotoDownloader\GitHub folders in the zip are your
                  reference copies (specification, launch materials, About text, release notes,
                  these instructions).

OPTION 1 - WEBSITE UPLOAD
-------------------------
1. Open the repository, choose Add file > Upload files.
2. Drag in the source files and the .github folder. Dragging a folder keeps its structure.
   Do not drag in the zip's docs or GitHub folders.
   Files with the same name replace the old ones. Up to 100 files per upload.
3. Message example: "Version 0.1.1.1: Linux uses GTK 2, Linux start-up window fixes; version 0.1.1.1: save .lrprev previews as JPG, four-digit year on cards; version 0.1.0 build 57: thumbnail sizes (small, medium, large, fit to window, Ctrl+wheel), file type and size on the cards, Lightroom previews (.lrprev), File Types Default button, compile check workflow". Commit directly to main.
4. The website cannot delete files. To delete: open the file, click the three dots, Delete file.
5. If a folder starts with a dot (.github) and will not drag in, use Add file > Create new file and type
   ".github/FUNDING.yml" as the name, then paste the contents.

OPTION 2 - GIT
--------------
   git clone https://github.com/RexAlfes/Photo-Downloader.git     (first time only)
   copy the new files over the cloned folder, then in that folder:
   git add -A
   git commit -m "Build 26: AVIF files supported"
   git push
git add -A also records deleted and renamed files.

COMPILE CHECK (GitHub Actions)
------------------------------
.github/workflows/build.yml compiles the project with lazbuild on Windows and on Linux (GTK 2) after every push and
pull request. See the result in the Actions tab, or as a green check or red cross beside each commit.
It only compiles: it never creates a release and never changes the build number. Run it by hand with
Actions > Build > Run workflow. If a run fails, open it and copy the log of the failed step.
If you use the website upload, create the file with Add file > Create new file and the name
".github/workflows/build.yml", then paste the contents.

GITHUB PAGES
------------
Settings > Pages > Source: Deploy from a branch > Branch: main > Folder: /docs > Save.
Wait for the green "pages build and deployment" run in the Actions tab, then reload with Ctrl+F5.
Whatever is in the repository's docs folder is public, so only copy files there that you want published.

REPOSITORY ABOUT
----------------
Gear icon beside About: paste the description, website and topics from GitHub_About.txt.

BASELINE TAG
------------
Build 42 is the baseline. After uploading: git tag baseline-build-42 && git push origin baseline-build-42
(or Releases > Draft a new release with the tag baseline-build-42, and tick pre-release).

RELEASE
-------
Releases > Draft a new release. Tag example: v0.1.1.1. Paste the matching release notes file.
Attach these files and tick "Set as a pre-release":
  PhotoDownloader.0.1.1.1.Win64.exe      (Windows 64-bit, single file)
  PhotoDownloader.0.1.1.1.Win64.zip      (Windows 64-bit, zipped copy of the exe)
  PhotoDownloader.0.1.1.1.linux64.tar.gz (Linux 64-bit; pack the executable in a tar.gz so it stays executable)
  User_Manual.0.1.1.1.odt                (User Manual, editable)
  User_Manual.0.1.1.1.md                 (User Manual, text)
Keep "win" or "linux" in each program file name (any capitalization): the website download buttons read the newest
release and label each file Windows or Linux from its name. Other files are listed as plain downloads.
