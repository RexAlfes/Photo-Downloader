GITHUB UPDATE INSTRUCTIONS - Photo Downloader
=============================================

Repository: https://github.com/RexAlfes/Photo-Downloader
Website:    https://rexalfes.github.io/Photo-Downloader/   (served from the docs folder on main)

WHAT GOES WHERE (unzip PhotoDownloader-Claude N.zip first)
------------------------------------------------------------
Normal upload   : *.pas, *.lpr, *.lpi, *.ico, README.md, .gitignore, .github/FUNDING.yml
Manual, as needed: the User Manual. Copy GitHub/docs/User_Manual.md into the repository's docs folder
                  (README.md links to it) whenever it changes.
Manual, as needed: the website page. Copy GitHub/docs/index.html into the repository's docs folder
                  only when you want the public site to change.
Never uploaded  : the PhotoDownloader\docs and PhotoDownloader\GitHub folders in the zip are your
                  reference copies (specification, launch materials, About text, release notes,
                  these instructions).

OPTION 1 - WEBSITE UPLOAD
-------------------------
1. Open the repository, choose Add file > Upload files.
2. Drag in the source files and the .github folder. Dragging a folder keeps its structure.
   Do not drag in the zip's docs or GitHub folders.
   Files with the same name replace the old ones. Up to 100 files per upload.
3. Message example: "Build 55: MP4/MOV/LRV/MP3 support, separate video file types, View menu in the right-click menu, renamed name clashes, status documentation". Commit directly to main.
4. The website cannot delete files. To delete: open the file, click the three dots, Delete file.
5. If a folder starts with a dot (.github) and will not drag in, use Add file > Create new file and type
   ".github/FUNDING.yml" as the name, then paste the contents.

OPTION 2 - GIT
--------------
   git clone https://github.com/RexAlfes/Photo-Downloader.git     (first time only)
   copy the new files over the cloned folder, then in that folder:
   git add -A
   git commit -m "Build 26: AVIF files supported"
   git push
git add -A also records deleted and renamed files.

GITHUB PAGES
------------
Settings > Pages > Source: Deploy from a branch > Branch: main > Folder: /docs > Save.
Wait for the green "pages build and deployment" run in the Actions tab, then reload with Ctrl+F5.
Whatever is in the repository's docs folder is public, so only copy files there that you want published.

REPOSITORY ABOUT
----------------
Gear icon beside About: paste the description, website and topics from GitHub_About.txt.

BASELINE TAG
------------
Build 42 is the baseline. After uploading: git tag baseline-build-42 && git push origin baseline-build-42
(or Releases > Draft a new release with the tag baseline-build-42, and tick pre-release).

RELEASE
-------
Releases > Draft a new release. Tag example: Build-55. Paste the matching release notes file.
Attach one file per platform and tick "Set as a pre-release":
  PhotoDownloader.0.1.0.build.55.win64.exe      (Windows 64-bit)
  PhotoDownloader.0.1.0.build.55.linux64.tar.gz (Linux 64-bit; pack the executable in a tar.gz so it stays executable)
Keep "win" or "linux" in each file name: the website download buttons read the newest release and label each file
Windows or Linux from its name.
