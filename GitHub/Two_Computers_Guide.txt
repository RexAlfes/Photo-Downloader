WORKING ON TWO COMPUTERS (Windows and Linux) WITH GIT AND GITHUB - Photo Downloader
=====================================================================================

The idea: the GitHub repository is the ONE true copy of the code. Each computer has a working
copy (a "clone"). You copy changes between computers with "push" (send to GitHub) and "pull"
(get from GitHub), never by copying files around by hand.

Daily rhythm (same on both computers)
-------------------------------------
  1. START of a session : Pull   (get what the other computer sent)
  2. Work, compile, test
  3. END of a session   : Commit (save a snapshot with a short message), then Push (send it)

If you forget step 1 you may edit an old copy, and Git will ask you to sort out the difference
later. So: pull first, always.

Which program to use
--------------------
Easiest: GitHub Desktop (Windows). It has buttons "Fetch/Pull origin", "Commit to main" and
"Push origin". On Linux the same steps work in a terminal (below), or with the community build
of GitHub Desktop.

Terminal version (works on both; open a terminal in the PhotoDownloader folder):
  git pull                       get the latest
  git status                     what did I change?
  git add -A                     take all my changes into the next snapshot
  git commit -m "short message"  save the snapshot, e.g. "Save lrprev as JPG"
  git push                       send it to GitHub

One-time setup on each computer
-------------------------------
  1. Install Git (Windows: git-scm.com; Linux: sudo apt install git).
  2. Tell Git who you are (once per computer):
       git config --global user.name  "Your Name"
       git config --global user.email "you@example.com"
  3. Get the code (once per computer; this creates the folder PhotoDownloader):
       git clone https://github.com/RexAlfes/Photo-Downloader PhotoDownloader
     GitHub asks you to sign in the first time you push (a browser window opens, or use a
     personal access token as the password; see "Signing in on Linux" below).
  4. Open PhotoDownloader.lpi in Lazarus as usual.

The version number file (the one thing to watch)
------------------------------------------------
The Lazarus IDE changes PhotoDownloader.lpi every time you compile: the build number goes up
by one on its own. lazbuild alone does not; on Linux, linux/build.sh raises it for you. Let it,
and commit the file with your other changes. Rules:
  * Always pull before you compile, and commit and push when you are done, so both computers
    count on from the same number.
  * If a pull still reports a conflict in PhotoDownloader.lpi, keep the higher BuildNr value,
    then:  git add PhotoDownloader.lpi   and   git commit

Branches (optional, later)
--------------------------
A branch is a separate line of work. Safe habit: do new work on a branch called "dev" and only
move it to "main" when it is tested.
    git switch -c dev              create and move to the branch "dev" (first time)
    git push -u origin dev         send the branch to GitHub (first time)
    ... later, when tested: on GitHub open a "Pull request" from dev to main and click Merge.
GitHub Actions (the Build tab on GitHub) compiles every push for Windows and Linux. A green
check means it compiles on both.

Marking a release
-----------------
When a bundle is stable and tested: set the version in PhotoDownloader.lpi (for example 0.1.1.1),
commit, then tag it:
    git tag v0.1.1.1
    git push origin v0.1.1.1
Then on GitHub: Releases > Draft a new release > choose the tag, paste the release notes, attach
the .exe / .zip / .tar.gz files (see "Git Instructions.txt").

Signing in on Linux (username and password do not work)
--------------------------------------------------------
GitHub no longer accepts your account password on the command line. When git asks for
"Password", it wants a PERSONAL ACCESS TOKEN instead:
  1. On github.com: your picture (top right) > Settings > Developer settings >
     Personal access tokens > Tokens (classic) > Generate new token (classic).
     Note: "Linux computer"; Expiration: for example 90 days; tick the scope "repo"
     (needed for the private plug-in repository too). Generate, then COPY the token
     (it is shown only once).
  2. Let git remember it, so you type it only once:
       git config --global credential.helper store
     (it is kept in ~/.git-credentials, readable only by you; "cache" instead of "store"
     keeps it in memory for 15 minutes only).
  3. git pull (or git push): Username = your GitHub user name, Password = paste the token.
     Nothing is shown while you paste; press Enter.
  If an old wrong password was stored, remove it first:  rm ~/.git-credentials
  Alternative: install the GitHub command-line tool (sudo apt install gh), then
  gh auth login  (choose HTTPS and "Login with a web browser") and  gh auth setup-git.

GitHub Desktop on Linux: a pull that seems to change nothing
--------------------------------------------------------------
  * "Fetch origin" only LOOKS for new commits. When it then shows "Pull origin" with a
    number, click it again: only Pull changes the files.
  * Desktop may have opened another copy of the folder. Repository > Show in your File
    Manager shows which folder it works on; it must be the folder you build in.
  * The private plug-in folder (Private/PennDOT_UAS_Plugin) is a repository of its own. Add it
    in Desktop separately (File > Add local repository) and pull it there as well.
  * Check in a terminal, in the folder:  git status  and  git log --oneline -3
    The newest line must match the newest commit on github.com.

If something goes wrong
-----------------------
  * "Your local changes would be overwritten": commit or discard your changes first
    (git stash saves them aside; git stash pop brings them back).
  * "Merge conflict": both computers changed the same lines. Open the file, look for the lines
    with <<<<<<< ======= >>>>>>>, keep the version you want, delete the marker lines, then
    git add -A and git commit. Tell Claude if you get stuck: paste the message.
  * Never "force push" (git push --force) unless you know exactly why.
